# 全部待办 · `user-all-tasks`

汇总全库未完成的待办，在首页直接勾选。

| 项 | 值 |
|---|---|
| 文件 | `all-tasks.js` |
| kind | `user-all-tasks` |
| 图标 / 强调色 | `list-todo` / `#2563eb` |
| 默认尺寸 | 4×8 |
| 设置面板 | 有 |

## 功能

- 扫描全库（或限定来源）的 `- [ ]` 待办，未完成项排在前面。
- 勾选后原子改写任务所在笔记的那一行，该条从列表移除。
- 点击任务文字或来源名，跳到原笔记对应行（支持 Ctrl/Cmd 新标签）。
- 列表在卡片内滚动，适合待办很多的情况。
- 任务状态识别：`[x]` 完成、`[/]` 或 `[>]` 进行中、其余为待办。

## 配置

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `sources` | string[] | `[]` | 限定来源：文件夹或单个笔记路径，多个取并集；空 = 全库 |
| `excludeFolders` | string[] | `[]` | 排除的文件夹 |

设置面板里两项都按「一行一个」填写，也接受逗号分隔。

## 数据来源

- 用 `app.metadataCache.getFileCache(file).listItems` 定位带 `task` 的条目，避免逐个读文件。
- 只对命中任务的文件 `cachedRead` 一次，取任务文字。
- 排序：未完成 → 进行中 → 已完成；同组按文件修改时间倒序。

## 读写行为

- 写入：`app.vault.process()` 原子改写目标行。
- 改写前校验该行内容与扫描时一致；不一致就报「文件已被修改，请刷新后重试」，不盲改。
- 兼容 CRLF / LF。

## 实现备注

- 旧版配置只有 `source` 字符串，`normalizeConfig` 会自动迁移到 `sources`。
- 样式注入 id：`hp-user-all-tasks-style`。
